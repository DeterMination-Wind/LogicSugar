# 合并内存（span）

> 返回 [教程目录](README.md) · 上一章 [链表](chain.md)

## 什么时候用

一块内存的容量不够，但你有好几块同样大小的 `cell` / `bank` / `world`，希望它们看起来像**一段连续的内存**：数组大到装不进单块 cell、矩阵要按行跨块排、或者你只是不想自己写 `i / 64` 和 `i % 64`。

`span` 就是给这段逻辑地址起的名字。它本身不搬数据，只在编译期把逻辑地址换算成「哪一块 + 格内偏移」，并把逻辑容量 `N * C` 交给数组/矩阵/容器声明的区间检查。

## 声明卡

```text
span <name> "<cell1 + cell3 + cell2>"
```

编辑器里卡片显示成一行表达式 `mem = cell1 + cell3 + cell2`：

- `+` 只表示**按书写顺序拼接**，不是加法，不参与 `op` 运算；
- 第一项是逻辑地址 0，第二个成员从地址 `C` 开始，第三个从 `2C` 开始……（`C` = 每格容量）；
- 个数不限，但至少要两块，且每块容量必须相同，否则编译报错；
- `mem` 可以直接当内存名用（`read x mem i` / `write v mem i`），也可以填进数组/矩阵/容器/位集/哈希表/集合/列表/堆/链表声明卡的内存字段：`array buf big 0 128`。

每格容量 C 的确定顺序：先看这个变量**在处理器里链接到的方块**（`memoryCapacity`，world-cell 也按真实的 512 算），链接不到时才按名字猜（`cellN` = 64、`bankN` / `worldN` = 512，与其它声明卡同一张表）。名字既没有链接、也不像链接名时是编译错误——寻址需要一个确定的除数。

## 转译示例

```text
span big "cell1 + cell2"
read x big i
```

产物（`C = 64`）：

```text
op idiv __ls_span_q i 64
op mod __ls_span_r i 64
select __ls_span_b equal __ls_span_q 0 cell1 0
select __ls_span_b equal __ls_span_q 1 cell2 __ls_span_b
read x __ls_span_b __ls_span_r
```

读一遍：`__ls_span_q = i / 64`（向下取整）决定用哪一块，`__ls_span_r = i % 64` 是格内地址，`select` 链把「第几块」换成真正的内存块变量，最后一条 `read` / `write` 落在它上面。

- 常量地址在编译期折叠成一条指令：`read x big 70` → `read x cell2 6`。
- 越界（负数，或者 `>= N*C`）时 `select` 链全部不命中，留在数字 `0`（空目标）上：读出来是空、写入不落盘，和原版越界 `read` / `write` 一致。
- 变量地址固定 `N+3` 条指令；省下来的是你的下标计算，不是指令数。

## 复杂度

| 操作 | 复杂度 |
| --- | --- |
| 常量地址 `read` / `write` | O(1)，1 条指令（编译期折叠） |
| 变量地址 `read` / `write` | O(1)，固定 `N+3` 条指令（N = 成员格数） |

数组/矩阵/容器的操作复杂度不变，只是每次访问多几条寻址指令。

## 使用须知

- **成员等容量**：混合容量是编译错误。`cell1 + cell2` 是 64 + 64；`cell1 + bank1` 是 64 + 512，不能拼。
- **名字不能撞链接**：`mem` 不能叫 `cell1` / `bank1` / `world1`（会遮住真实链接名），也不能与数组/矩阵/函数重名。
- **不搬数据**：`span` 只是别名，数据仍然分块存放；换存档/换地图后块里的内容照旧按物理地址分布。
- **只想把多块内存当一段用**：只声明 span 并直接 `read` / `write` 就够了；想让下标糖 `buf[i]` 可用，再声明 `array buf big 0 <size>`（`size <= N*C`）。
- **批量运算不支持跨格**：`array_sum` / `array_sort` 这类注入函数只对单块内存寻址，内存名是 span 时编译期直接报错，请改成对单块数组调用，或者自己用下标循环。
- **重开存档**：`span` 卡只存在于 Sugar 载体里；纯原版 mlog（没有载体）不会凭空长出它。用 `buf[i]` 的 Expr 卡靠卡片自己写的 `# @ls-expr-card` 标记随载体一起恢复：变量下标是多行地址链、由折叠还原；常量下标是单行 `read`，脱离标记就无法与同 cell 上的原版读积木区分（声明不替它认领身份）。≤5.7.1 存档里的单行下标卡没有标记，重开会显示成原版读写积木：产物不变，重新拖一张 Expr 卡即可。
- **联机兼容**：产物是纯原版 `op` / `select` / `read` / `write`，其它客户端不需要装模组。
