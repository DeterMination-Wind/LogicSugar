# 记录（record）

> 返回 [教程目录](README.md) · 上一章 [矩阵](matrix.md) · 下一章 [栈](stack.md)

## 什么时候用

把几个相关的值打包成一个「对象」：单位状态 `hp/mp/x/y`、配方参数、多个返回值。记录本身不占内存，字段就是普通 mlog 变量，读写都是 O(1)。

## 声明卡

```text
record <name> <f1> <f2> ... <f8>
```

| 规则 | 说明 |
| --- | --- |
| 字段数 | 至少 1 个，最多 8 个 |
| 空槽 | 用 `~` 占位，卡固定 10 个 token |
| 字段名 | 匹配 `[A-Za-z_][A-Za-z0-9_]*`，大小写敏感 |
| 保留前缀 | 名字与字段都不能用 `__ls_` 开头 |

示例：

```text
record p hp mp x y ~ ~ ~ ~
```

表示记录 `p` 有 4 个字段；字段变量分别是 `p_hp`、`p_mp`、`p_x`、`p_y`。

## 成员读写

| 写法 | 含义 | 转译 |
| --- | --- | --- |
| `p.hp` | 读字段 | `op add <结果> p_hp 0` |
| `p.hp = expr` | 写字段 | 先编译 expr，再 `op add p_hp <值> 0` |

记录没有函数表，成员访问就是唯一操作。

## 转译示例

读：

```text
record p f1 f2 ~ ~ ~ ~ ~ ~
x = p.f1
```

产物：

```text
op add x p_f1 0
```

写成表达式的一部分：

```text
x = p.f1 + p.f2
```

产物：

```text
op add _0 p_f1 0
op add _1 p_f2 0
op add x _0 _1
```

写：

```text
record p f1 f2 ~ ~ ~ ~ ~ ~
p.f1 = 5
p.f2 = a + 1
```

产物：

```text
op add p_f1 5 0
op add _0 a 1
op add p_f2 _0 0
```

字段变量是普通变量，会出现在游戏的变量列表里，方便在变量浏览器/调试中查看。

## 复杂度

| 操作 | 复杂度 |
| --- | --- |
| `p.f1` 读 | O(1)，一条 `op add` |
| `p.f1 = v` 写 | O(1)，一条 `op add` |

## 使用须知

- **声明卡不产指令**：`record` 行不会出现在产物里；它只告诉编译器「`p` 是记录、字段有哪些」。
- **字段是普通变量**：`p_hp` 等会随着处理器重新载入回到未赋值（0/NaN）状态；记录不提供跨存档持久化。需要持久化请显式写进内存块或使用 `map`/`list` 等结构。
- **大小写敏感**：`p.F1` 与 `p.f1` 不是同一个字段；写错字段名会编译报错，不会静默创建新变量。
- **最多 8 个字段**：超过 8 个请拆分记录，或用 `array` / `list`。
- **字段名不能与数组/其它记录冲突**：字段变量形如 `<name>_<field>`，与同名数组、矩阵、函数、其它记录字段冲突会在编译期报错。
- **sensor 兼容**：只有「基底是已声明记录名」时才走记录展开。`unit.health` 这类未声明为记录的成员访问仍走原版 sensor；反过来，已声明为记录的变量出现未知成员会按笔误报错（不会退回 sensor）。
- **不能嵌套记录**：字段只能是标量；需要嵌套结构请用不同记录/数组，或 [链](chain.md) 自己组织。
